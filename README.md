# neptun-meters-bot

Telegram-бот для счётчиков воды Neptun (и других устройств Tuya / Smart Life):

- снимает показания счётчиков воды двумя способами на выбор (`READ_SOURCE`): через **облачный Tuya API** или **по локальной сети** (tinytuya), по кнопке, раз в сутки автоматически и в ежемесячный отчёт;
- предупреждает, если показаний давно нет;
- передаёт показания на mos.ru («Электронный дом»).

Опрос датчиков протечки и кранов в бота **не входит**: защиту от протечек выполняет сам контроллер Neptun.

## Возможности

- Кнопки: 📊 Показания, 🩺 Состояние, 🔧 Все DP, 📤 mos.ru.
- Автосъём показаний раз в сутки (`DAILY_READ_HOUR`), история хранится в базе.
- Тревога 📭, если показаний нет `NO_DATA_ALERT_DAYS` (по умолчанию 3) дня подряд, и сообщение о восстановлении.
- Ежемесячный отчёт в выбранное число (например, 23-го) с расходом за период.
- Передача на mos.ru: вход по QR, проверка значений, отправка с подтверждением кнопкой или автоматически.
- Бот отвечает только в чате `TELEGRAM_CHAT_ID`.

## Требования

- Docker и Docker Compose
- Для `cloud` и `auto`: аккаунт разработчика на [iot.tuya.com](https://iot.tuya.com); для `local` и `auto`: бот в одной локальной сети с устройством
- Telegram-бот (токен от [@BotFather](https://t.me/BotFather))

## Выбор источника показаний

| `READ_SOURCE` | Как читает | Плюсы | Минусы |
|---|---|---|---|
| `cloud` (по умолчанию) | Tuya Cloud API | работает из любой сети, бот можно держать на VPS | тратит вызовы API (лимит 26 000 в месяц), зависит от облака и триала IoT Core |
| `local` | Локальная сеть по протоколу Tuya (tinytuya) | без облака и без лимита API, быстрее | бот должен быть в одной сети с Neptun; нужен local key и IP; устройство принимает одно соединение за раз |
| `auto` | Сначала локально, при сбое облако | надёжнее всего | нужны и ключи облака, и настройки локальной сети |

Локально Neptun Smart отдаёт показания отдельными DP 137–144, бот называет их `counter1`…`counter8` (литры). Остальные известные DP тоже получают коды, как в облаке (`status_crane_group_1`, `notifications` и т. д.). Коды в `SENSORS` и в настройках mos.ru остаются теми же, что и для облака.

Для локального доступа бот создаёт устройство так же, как проверенный скрипт на базе проекта tuya-local: версия протокола задаётся явно, а автоопределение типа `device22` отключено (для 22-символьных ID оно приводит к ошибкам `904`/`914`). Для этого нужен `tinytuya==1.21.1`, он уже указан в `requirements.txt`.

**Настройка локального режима**

1. Закрепите IP устройства в роутере и впишите его в `TUYA_LOCAL_IP`.
2. `TUYA_LOCAL_KEY` лучше оставить **пустым**: бот один раз возьмёт актуальный ключ из облака (нужны ключи облака) и запомнит; если ключ позже сменится, бот сам это заметит и обновит. Если задаёте вручную, копируйте точно из `devices.json` и берите в одинарные кавычки, когда в ключе есть `$`.
3. Отправьте боту `/lan`: он проверит порт, ключ и версию протокола и покажет расшифрованные счётчики. Закрепите найденную версию в `TUYA_LOCAL_VERSION` (для Neptun Smart это `3.4`).
4. Поставьте `READ_SOURCE=local` (или `auto`) и пересоздайте контейнер: `docker compose up -d --force-recreate`.

Источник и время последнего чтения видны в «🩺 Состояние».

## 1. Tuya Cloud

1. Зарегистрируйтесь на iot.tuya.com (отдельный аккаунт, не Smart Life), создайте Cloud Project (*Smart Home*, дата-центр *Central Europe* = `eu`).
2. Подключите сервисы **IoT Core**, **Authorization**, **Device Status Notification** (и при необходимости **Device Management**).
3. **Devices → Link App Account**: привяжите Smart Life по QR-коду (в приложении: **Я → значок сканера**).
4. Из **Overview** возьмите `Access ID`, `Access Secret`; из **Devices** возьмите `Device ID`.

> Бесплатный триал IoT Core нужно периодически продлевать (кнопка *Extend Trial Period* в проекте). Если забыть, API перестанет отвечать, а бот через `NO_DATA_ALERT_DAYS` дней пришлёт тревогу.

## 2. Telegram

1. Создайте бота у @BotFather и получите токен.
2. Узнайте chat id (@userinfobot для личного, @GetIDsBot для группы; у групп id с минусом).
3. В группе сделайте бота администратором, иначе он не получит нажатия кнопок.
4. Для отчётов в канал укажите `NOTIFY_CHAT_ID` (бот должен быть админом канала). Кнопки в каналах не работают.

## 3. Запуск

```bash
cp .env.example .env
# заполните .env
docker compose up -d --build
docker compose logs -f
```

Отправьте боту `/start`, появятся кнопки.

## 4. Определение кодов счётчиков (SENSORS)

Нажмите **🔧 Все DP**: бот пришлёт все DP устройства с кодами. Для Neptun Smart счётчики лежат в `counter1`…`counter8`, значения в литрах. Впишите нужные в `.env`:

```env
SENSORS=counter7:Горячая вода:0.001:м³,counter8:Холодная вода:0.001:м³
```

Формат: `код:Название:масштаб:единица`, несколько через запятую.

| `/diag` | Диагностика облака (4 вызова API) |
| `/mosru_login`, `/mosru_status`, `/mosru_logout` | Вход, состояние и выход из mos.ru |

## Передача показаний на mos.ru

Работает через тот же API, что и сайт [ed.mos.ru](https://ed.mos.ru/lk/counters/). Клиент портала взят из проекта [kostinos/hass-mosru-water](https://github.com/kostinos/hass-mosru-water) (MIT): файл `mosru_api.py`, лицензия в `LICENSE-hass-mosru-water`. Подходит для квартир, подключённых к «Электронному дому» (Москва).

> Это неофициальный API: если портал его изменит, передача может перестать работать. Бот ничего не удаляет и не перезаписывает на портале: если за месяц показание уже внесено, он просто сообщит об этом.

**Настройка**

1. В `.env` задайте `MOSRU_MODE=confirm` (спрашивать кнопкой) или `auto`. Убедитесь, что `counter7`/`counter8` есть в `SENSORS`, а `MOSRU_COLD_CODE`/`MOSRU_HOT_CODE` указывают на нужные DP.
2. Перезапустите бота и отправьте `/mosru_login`. Бот пришлёт QR-код: отсканируйте его в приложении «mos.ru» или «Госуслуги Москвы». Если mos.ru попросит код (аутентификатор или SMS), отправьте его боту одним сообщением.
3. Если квартир несколько, выберите нужную кнопкой. Счётчики ХВС и ГВС определяются автоматически; если нет, бот покажет их id, и вы впишете `MOSRU_COLD_ID`/`MOSRU_HOT_ID`.
4. `/mosru_status` покажет текущие показания на портале и открыт ли приём.

**Как это работает**

- В назначенный день (`MOSRU_SUBMIT_DAY`, `MOSRU_SUBMIT_HOUR`) бот берёт показания Neptun из облака (1 вызов API), сверяет их с порталом и:
  - `confirm`: присылает «Передать? ✅ / ❌» (напоминает раз в сутки, пока не передано);
  - `auto`: отправляет сам и сообщает результат (при ошибке повторяет раз в час).
- Кнопка **📤 mos.ru** запускает ту же процедуру вручную в любой момент.
- Портал принимает только целые м³, поэтому 1433.267 м³ уйдёт как 1433.
- Перед отправкой проверяется: показание не меньше портального и не выросло больше чем на `MOSRU_MAX_DELTA` (100 м³); приём показаний открыт. При проблеме ничего не пишется, а бот объясняет причину.
- Раз в 45 минут бот обращается к порталу, чтобы сессия не истекала между отправками. Если сессия всё же истекла, придёт 🔑 с просьбой выполнить `/mosru_login`.

**Безопасность**

- Сессионные cookies mos.ru хранятся в `./data/bot.db` как секрет: не публикуйте эту папку.
- QR-код и коды подтверждения безопаснее запрашивать в личном чате с ботом, а не в общей группе.
- Ошибка `HTTP 451` при входе может означать проверку возраста: проверьте дату рождения в профиле mos.ru.

| `TUYA_LOCAL_KEY` | пусто | Local key (пусто = взять из облака один раз) |
| `TUYA_LOCAL_VERSION` | `auto` | Версия протокола: `auto`, `3.3`, `3.4`, `3.5` |
| `LOCAL_RETRIES` | `3` | Повторов локального запроса при пустом ответе |
| `TUYA_REGION` | `eu` | `eu`, `us`, `cn`, `in` |
| `TUYA_ACCESS_ID`, `TUYA_ACCESS_SECRET`, `TUYA_DEVICE_ID` | | Данные проекта и устройства |
| `API_MONTHLY_LIMIT` | `26000` | Лимит вызовов API, только для отображения |
| `TELEGRAM_BOT_TOKEN` | | Токен бота |
| `TELEGRAM_CHAT_ID` | | Чат с кнопками (единственный, кому отвечает бот) |
| `NOTIFY_CHAT_ID` | пусто | Куда слать отчёты и тревоги |
| `TZ` | `Europe/Belgrade` | Часовой пояс |
| `SENSORS` | пусто | Счётчики для показаний |
| `DAILY_READ_HOUR` | `8` | Час ежедневного снятия показаний (`-1` = выключено) |
| `DAILY_RETRY_MINUTES` | `60` | Повтор после неудачного снятия, мин |
| `DAILY_REPORT` | `false` | `true` = присылать показания в чат каждый день |
| `NO_DATA_ALERT_DAYS` | `3` | Нет показаний столько дней, значит тревога |
| `ALERT_REPEAT_HOURS` | `24` | Напоминание о нерешённой проблеме |
| `MONTHLY_REPORT_DAY` | `0` | Число месяца для ежемесячного отчёта (`0` = выключен) |
| `MONTHLY_REPORT_HOUR` | `9` | Час отправки по `TZ` |
| `MOSRU_MODE` | `off` | `off`, `confirm` или `auto` |
| `MOSRU_SUBMIT_DAY` / `MOSRU_SUBMIT_HOUR` | 20 / 9 | День и час передачи (по умолчанию как у ежемесячного отчёта) |
| `MOSRU_COLD_CODE` / `MOSRU_HOT_CODE` | `counter8` / `counter7` | DP холодной и горячей воды |
| `MOSRU_MAX_DELTA` | `100` | Макс. рост относительно портала, м³ |
| `MOSRU_USER_PLACE_ID`, `MOSRU_COLD_ID`, `MOSRU_HOT_ID` | пусто | Ручная настройка квартиры и счётчиков |

## Расход API

При `READ_SOURCE=local` вызовы API не тратятся вообще (кроме одного при получении local key из облака). Ниже расход при `cloud`:

- Ежедневное снятие: 1 вызов в сутки (около 30 в месяц), при неудаче повтор раз в час до успеха.
- Кнопка «📊 Показания»: 1 вызов. Ежемесячный отчёт и передача на mos.ru: по 1 вызову в месяц.
- `/diag`: 4 вызова.

Счётчик вызовов за месяц виден в «🩺 Состояние».

## Данные

Состояние хранится в `./data/bot.db` (SQLite): сессия mos.ru, история показаний, снимок для ежемесячного отчёта, счётчик вызовов.

## Частые проблемы

| Симптом | Решение |
|---|---|
| `permission deny` | Не подключены IoT Core / Authorization либо истёк триал IoT Core. |
| Устройств нет в проекте | Регион не совпадает с дата-центром проекта или не привязан аккаунт Smart Life. |
| «нет данных (код)» | Неверный код в `SENSORS`. Нажмите «🔧 Все DP» и сверьте. |
| Локально: `Err 904` / `914` | Неверная версия протокола или ключ. Выполните `/lan`: бот переберёт версии и покажет, какая отвечает; проверьте длину ключа (должна быть 16, символ `$` в `.env` берите в кавычки). |
| Локально: `Err 901`, таймаут | Устройство недоступно по сети: проверьте IP, что бот в той же сети, и что приложение Smart Life не держит соединение. |
| Бот молчит в группе | Сделайте бота админом группы, проверьте `TELEGRAM_CHAT_ID` (у групп минус). |
| `Conflict: terminated by other getUpdates` | Запущен второй экземпляр с тем же токеном. |
| Старая кнопка в чате | Отправьте `/start`. |
