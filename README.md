# tuya-meters-bot

Telegram-бот для Neptun (и других устройств Tuya / Smart Life):

- **Показания счётчиков** идут через облачный Tuya API: по кнопке и ежемесячным отчётом. Это 1 вызов API за раз.
- **Алерты** (протечка, краны, потеря связи) идут через **локальную сеть** по протоколу Tuya (tinytuya). Лимит API они не тратят.

## Возможности

- Кнопки: 📊 Показания, 🩺 Состояние, 🔧 Все DP.
- Автоматическое снятие показаний раз в сутки (`DAILY_READ_HOUR`), история хранится в базе. Тревога 📭, если показаний нет `NO_DATA_ALERT_DAYS` (по умолчанию 3) дня подряд.
- Ежемесячный отчёт в выбранное число (например, 23-го) с расходом за период.
- Тревога 🚨, когда DP протечки или кранов отличается от нормы. Повторяется, пока всё не вернётся в норму, потом приходит ✅.
- Тревога 🔴, если устройство недоступно по локальной сети дольше N минут.
- Бот отвечает только в чате `TELEGRAM_CHAT_ID`.

## Требования

- Docker и Docker Compose на машине **в той же локальной сети**, что и устройство (Linux-хост, мини-ПК, Raspberry Pi, NAS).
- Аккаунт разработчика на [iot.tuya.com](https://iot.tuya.com) (облако нужно для показаний и один раз для local key).
- Telegram-бот (токен от [@BotFather](https://t.me/BotFather)).

## 1. Tuya Cloud

1. Зарегистрируйтесь на iot.tuya.com, создайте Cloud Project (*Smart Home*, дата-центр *Central Europe* = `eu`).
2. Подключите сервисы **IoT Core**, **Authorization**, **Device Status Notification** (и при необходимости **Device Management**).
3. **Devices → Link App Account**: привяжите Smart Life по QR-коду (в приложении: **Я → значок сканера**).
4. Из **Overview** возьмите `Access ID`, `Access Secret`; из **Devices** возьмите `Device ID`.

## 2. Локальная сеть

1. Найдите IP устройства в роутере и **закрепите** его за устройством (DHCP reservation), иначе после смены адреса алерты перестанут работать.
2. Впишите IP в `TUYA_LOCAL_IP`.
3. `TUYA_LOCAL_KEY` можно оставить пустым: бот один раз возьмёт ключ из облака (1 вызов API) и запомнит. Либо получите его сами через `python -m tinytuya wizard`.
4. `TUYA_LOCAL_VERSION=auto`: бот сам подберёт версию протокола (3.4, 3.3, 3.5, 3.2). Её можно задать вручную.

Порт устройства 6668/tcp должен быть доступен из контейнера. Из обычной сети Docker (bridge) локальные адреса доступны, `network_mode: host` не нужен.

> Многие устройства Tuya принимают только одно локальное соединение. Бот держит запросы короткими (раз в 15 секунд), но если приложение Smart Life или другая интеграция постоянно держит локальное соединение, возможны обрывы.

## 3. Telegram

1. Создайте бота у @BotFather и получите токен.
2. Узнайте chat id (@userinfobot для личного, @GetIDsBot для группы; у групп id с минусом).
3. Если используете группу, сделайте бота администратором, иначе он не получит нажатия кнопок.
4. Для алертов в канал укажите `NOTIFY_CHAT_ID` (бот должен быть админом канала). Кнопки в каналах не работают.

## 4. Запуск

```bash
cp .env.example .env
# заполните .env
docker compose up -d --build
docker compose logs -f
```

В логе появятся строки `Локальное подключение: <IP>, протокол 3.x` и `Старт. Владелец chat_id=...`. Отправьте боту `/start`.

## Определение кодов счётчиков (SENSORS)

Нажмите **🔧 Все DP**: бот пришлёт все DP устройства (локально, если связь есть) с кодами. Впишите счётчики в `SENSORS` в формате `код:Название:масштаб:единица`:

```env
SENSORS=counter7:Горячая вода:0.001:м³,counter8:Холодная вода:0.001:м³
```

Для Neptun значения в литрах, поэтому масштаб `0.001` даёт м³.

## Тревоги по протечке

`LEAK_WATCH` задаёт DP и норму: `code:Название:норма`. Если значение отличается от нормы, приходит 🚨. По умолчанию:

| DP | Норма | Что это, вероятно |
|---|---|---|
| `status_wire_line` | `0` | проводные датчики |
| `status_rf_sensor` | `null` | беспроводные датчики |
| `notifications` | `0` | код оповещения |
| `status_crane_group_1/2` | `true` | краны (перекрытие = срабатывание) |

Значения при протечке зависят от модели. **Проверьте тревогу на практике** (смочите датчик) и при необходимости поправьте `LEAK_WATCH`. Локальные данные приходят с числовыми id DP; бот сопоставляет их с кодами по данным из облака (один раз, автоматически). Можно указывать и числовой id напрямую.

## Параметры (.env)

| Переменная | По умолчанию | Описание |
|---|---|---|
| `TUYA_REGION` | `eu` | `eu`, `us`, `cn`, `in` |
| `TUYA_ACCESS_ID`, `TUYA_ACCESS_SECRET`, `TUYA_DEVICE_ID` | | Данные проекта и устройства |
| `API_MONTHLY_LIMIT` | `26000` | Лимит вызовов API, только для отображения |
| `TELEGRAM_BOT_TOKEN` | | Токен бота |
| `TELEGRAM_CHAT_ID` | | Чат с кнопками (единственный, кому отвечает бот) |
| `NOTIFY_CHAT_ID` | пусто | Куда слать алерты и отчёты |
| `SENSORS` | пусто | Счётчики для показаний |
| `DAILY_READ_HOUR` | `8` | Час ежедневного снятия показаний по `TZ` (`-1` = выключено) |
| `DAILY_RETRY_MINUTES` | `60` | Повтор после неудачного снятия, мин |
| `DAILY_REPORT` | `false` | `true` = присылать показания в чат каждый день |
| `NO_DATA_ALERT_DAYS` | `3` | Нет показаний столько дней, значит тревога |
| `MONTHLY_REPORT_DAY` | `0` | Число месяца для отчёта (`0` = выключен) |
| `MONTHLY_REPORT_HOUR` | `9` | Час отправки по `TZ` |
| `TZ` | `Europe/Belgrade` | Часовой пояс |
| `TUYA_LOCAL_IP` | пусто | IP устройства в LAN (пусто = алертов нет) |
| `TUYA_LOCAL_KEY` | пусто | Local key (пусто = взять из облака) |
| `TUYA_LOCAL_VERSION` | `auto` | Версия протокола |
| `LOCAL_POLL_INTERVAL` | `15` | Период локального опроса, сек |
| `OFFLINE_ALERT_MINUTES` | `10` | Нет связи дольше N минут, значит тревога |
| `ALERT_REPEAT_HOURS` | `24` | Напоминание о потере связи |
| `LEAK_WATCH` | см. выше | DP протечки и норма |
| `LEAK_REPEAT_MINUTES` | `30` | Повтор тревоги по протечке |

## Расход API

- Кнопка «📊 Показания»: 1 вызов.
- Ежедневное снятие: 1 вызов в сутки (около 30 в месяц), при неудаче повтор раз в час до успеха.
- Ежемесячный отчёт: 1 вызов в месяц.
- Local key и соответствие DP: несколько вызовов один раз (и при смене ключа).
- `/diag`: 4 вызова.
- Локальные алерты: 0 вызовов.

Счётчик вызовов за месяц виден в «🩺 Состояние».

## Данные

Состояние хранится в `./data/bot.db` (SQLite): история показаний, снимок для ежемесячного отчёта, соответствие DP, local key, счётчик вызовов.

## Частые проблемы

| Симптом | Решение |
|---|---|
| «Нет связи по LAN», в логе `Check device key or version` / ошибка 914 | Неверная версия протокола или ключ. Поставьте `TUYA_LOCAL_VERSION=3.3` или `3.4`, очистите `TUYA_LOCAL_KEY`, чтобы бот взял свежий. |
| «Нет связи по LAN», таймаут | Неверный IP, устройство в другой подсети или занято другим локальным клиентом. |
| `permission deny` при показаниях | Не подключены IoT Core / Authorization либо истёк триал. |
| Нет данных по кодам в локальном режиме | Соответствие DP ещё не получено из облака (подождите 10 минут или нажмите «📊 Показания»). Можно указать числовой id в `LEAK_WATCH`. |
| Бот молчит в группе | Сделайте бота админом группы, проверьте `TELEGRAM_CHAT_ID` (у групп минус). |
| `Conflict: terminated by other getUpdates` | Запущен второй экземпляр с тем же токеном. |
| Старая кнопка в чате | Отправьте `/start`. |

## Безопасность

Не коммитьте `.env` и `data/`: там ключи Tuya, токен бота и local key.
