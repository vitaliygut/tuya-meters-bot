# tuya-meters-bot

Telegram-бот для получения показаний счётчиков с устройств Tuya / Smart Life (например, Neptun) через Tuya Cloud API.

## Возможности

- Кнопки в Telegram: текущие показания, состояние устройства, все DP.
- История показаний в SQLite (по умолчанию каждые 5 минут).
- Уведомления о проблемах:
  - Tuya Cloud недоступен;
  - устройство офлайн;
  - нет новых показаний (по умолчанию 48 часов);
  - показания не меняются (опционально).
- Тревоги по DP протечки и кранов Neptun (срабатывание датчиков, закрытие кранов) с повтором, пока значение не вернётся в норму.
- Сообщение о восстановлении, когда проблема ушла.
- Опциональный автоотчёт по расписанию.
- Ежемесячный отчёт в выбранное число (например, 23-го) с расходом за период.
- Бот отвечает только владельцу (`TELEGRAM_CHAT_ID`).

## Требования

- Docker и Docker Compose
- Аккаунт разработчика на [iot.tuya.com](https://iot.tuya.com)
- Telegram-бот (токен от [@BotFather](https://t.me/BotFather))

## 1. Настройка Tuya Cloud

1. Зарегистрируйтесь на iot.tuya.com (отдельный аккаунт, не Smart Life).
2. Создайте проект: **Cloud → Development → Create Cloud Project**.
   - Development Method: *Smart Home*
   - Data Center: для России и Европы обычно *Central Europe* (`eu`). Если устройства не видны, попробуйте *Western Europe*.
3. Подключите сервисы **IoT Core**, **Authorization** и **Device Status Notification**. Для проверки онлайн-статуса может понадобиться также **Device Management**.
4. Привяжите приложение: **Devices → Link App Account → Add App Account**, отсканируйте QR-код в Smart Life (**Я → значок сканера** в правом верхнем углу) и выберите автоматическую привязку всех устройств.
5. На вкладке **Overview** скопируйте `Access ID` и `Access Secret`. В списке **Devices** скопируйте `Device ID` счётчика.

> Бесплатный триал IoT Core нужно периодически продлевать (кнопка *Extend Trial Period* в проекте). Если забыть, API перестанет отвечать, а бот пришлёт уведомление о недоступности Tuya Cloud.

## 2. Настройка Telegram

1. Создайте бота у @BotFather и получите токен.
2. Узнайте свой chat id, например у @userinfobot.
3. Напишите своему боту любое сообщение, иначе он не сможет писать вам первым.

### Уведомления в канал (необязательно)

Кнопки и команды в каналах не работают, поэтому управление идёт в личке с ботом, а канал используется только для уведомлений.

1. Добавьте бота в канал **администратором** с правом публикации сообщений.
2. Узнайте id канала (вида `-1001234567890`), например, переслав пост из канала боту @userinfobot или @getidsbot.
3. Впишите его в `NOTIFY_CHAT_ID` в `.env`.

## 3. Запуск

```bash
cp .env.example .env
# заполните .env
docker compose up -d --build
docker compose logs -f
```

Затем отправьте боту `/start`, появятся кнопки.

## 4. Определение кодов счётчиков (SENSORS)

Название и коды DP зависят от модели устройства, поэтому при первом запуске:

1. Оставьте `SENSORS` пустым.
2. Нажмите **🔧 Все DP**: бот пришлёт все коды и значения устройства.
3. Найдите коды счётчиков (например, `water_use`, `cold_water`) и сверьте значения с приложением Smart Life, чтобы подобрать масштаб (часто делят на 10, 100 или 1000).
4. Впишите их в `.env` в формате `код:Название:масштаб:единица`, несколько через запятую:

```env
SENSORS=cold_water:Холодная вода:0.001:м³,hot_water:Горячая вода:0.001:м³
```

5. Перезапустите: `docker compose up -d`.

## Кнопки бота

| Кнопка | Что делает |
|---|---|
| 📊 Показания | Запрашивает текущие значения и записывает их в историю |
| 🩺 Состояние | Онлайн ли устройство, время последних данных, активные проблемы |
| 🔧 Все DP | Все коды и значения устройства (для отладки и настройки) |

## Параметры (.env)

| Переменная | По умолчанию | Описание |
|---|---|---|
| `TUYA_REGION` | `eu` | Регион дата-центра: `eu`, `us`, `cn`, `in` |
| `TUYA_ACCESS_ID` | | Access ID проекта |
| `TUYA_ACCESS_SECRET` | | Access Secret проекта |
| `TUYA_DEVICE_ID` | | ID устройства |
| `TELEGRAM_BOT_TOKEN` | | Токен бота |
| `TELEGRAM_CHAT_ID` | | Ваш chat id (единственный, кому отвечает бот, здесь работают кнопки) |
| `NOTIFY_CHAT_ID` | пусто | Канал или группа для уведомлений и автоотчётов. Пусто = личный чат |
| `SENSORS` | пусто | Список счётчиков (см. выше) |
| `POLL_INTERVAL` | `300` | Как часто опрашивать устройство, сек |
| `REPORT_INTERVAL` | `0` | Автоотчёт в чат, сек (`86400` = раз в сутки, `0` = выключен) |
| `MONTHLY_REPORT_DAY` | `0` | Число месяца для ежемесячного отчёта (`0` = выключен), например `23` |
| `MONTHLY_REPORT_HOUR` | `9` | Час отправки (0-23) по времени `TZ` |
| `TZ` | `Europe/Belgrade` | Часовой пояс контейнера |
| `LEAK_WATCH` | см. ниже | DP для контроля протечек/кранов в формате `code:Название:норма` |
| `LEAK_REPEAT_MINUTES` | `30` | Повтор тревоги, пока значение не в норме, мин |
| `NO_DATA_ALERT_HOURS` | `48` | Нет новых показаний столько часов, значит уведомление |
| `NO_CHANGE_ALERT_HOURS` | `0` | Показания не меняются столько часов, значит уведомление (`0` = выключено) |
| `OFFLINE_ALERT_MINUTES` | `30` | Устройство офлайн дольше N минут, значит уведомление |
| `API_FAIL_ALERT_MINUTES` | `30` | Tuya Cloud недоступен дольше N минут, значит уведомление |
| `ALERT_REPEAT_HOURS` | `24` | Как часто напоминать о нерешённой проблеме |
| `RETRY_INTERVAL` | `60` | Повтор опроса после ошибки, сек |
| `DB_PATH` | `/data/readings.db` | Путь к базе внутри контейнера |

## Датчики протечки

Бот следит за DP, перечисленными в `LEAK_WATCH` (формат `code:Название:норма`). Как только значение отличается от нормы, приходит сообщение 🚨, которое повторяется каждые `LEAK_REPEAT_MINUTES` минут, пока всё не вернётся в норму, после чего придёт ✅.

По умолчанию для Neptun следим за `status_wire_line`, `status_rf_sensor`, `notifications`, `status_crane_group_1` и `status_crane_group_2` с нормой при штатной работе. Точные значения при протечке зависят от модели: **проверьте тревогу на практике**, смочив датчик, и при необходимости поправьте `LEAK_WATCH` по тому, что покажет «🔧 Все DP».

Скорость реакции зависит от `POLL_INTERVAL` (по умолчанию 5 минут). Для быстрых тревог уменьшите его, но учтите месячный лимит вызовов API бесплатного тарифа Tuya (каждый опрос делает 2 запроса).

## Данные

История хранится в `./data/readings.db` (SQLite, том `./data:/data`). Удалите файл, чтобы сбросить историю.

## Частые проблемы

| Симптом | Причина и решение |
|---|---|
| `permission deny` | Не подключены сервисы IoT Core или Authorization, либо истёк триал IoT Core. Проверьте в проекте на iot.tuya.com. |
| Устройств нет в проекте | Регион не совпадает с дата-центром проекта или не привязан аккаунт Smart Life. |
| Ошибка на запросе онлайн-статуса | Подключите сервис Device Management в проекте. |
| Бот молчит | Проверьте `TELEGRAM_CHAT_ID` (бот игнорирует всех остальных) и что вы писали боту первым. |
| «нет данных (код)» | Неверный код в `SENSORS`. Нажмите «🔧 Все DP» и сверьте. |
| `Conflict: terminated by other getUpdates` | Тот же токен используется другим запущенным экземпляром бота. Остановите лишний. |

## Безопасность

- Не коммитьте `.env` в git: в нём ключи Tuya и токен бота. Добавьте его в `.gitignore`.
- Доступ к боту ограничен по `TELEGRAM_CHAT_ID`.
